Tingkat Kematangan Indikator Statistik Sektoral

Penjelasan teknis indikator kematangan implementasi Satu Data Indonesia di Kota Bandung, mencakup dimensi Kualitas Data dan Pemanfaatan Data. Setiap indikator dinilai pada skala 1-5 sesuai kerangka Penilaian Kematangan Statistik Sektoral BPS dan Perpres 39/2019 tentang Satu Data Indonesia.

Dimensi Kualitas Data menilai kemampuan organisasi perangkat daerah penghasil data statistik sektoral dalam menjamin data yang dihasilkan memenuhi standar aktualitas, ketepatan waktu diseminasi, ketersediaan, akses media, format, keterbandingan, dan konsistensi. Penilaian mengacu pada Perpres 39/2019 tentang Satu Data Indonesia dan Perka BPS tentang Penyelenggaraan Statistik Sektoral.
1
Tingkat Kematangan Penjaminan Aktualitas Data
Aktualitas · Indikator Kualitas Data
Definisi

Kemampuan walidata/OPD penghasil data dalam memastikan data yang disebarkan mencerminkan kondisi terkini sesuai periode referensi yang dijanjikan, sehingga selisih antara reference period dan tanggal rilis dapat dipertanggungjawabkan.

Tujuan

Meminimalkan gap antara periode referensi data dan waktu publikasi sehingga data tetap relevan sebagai dasar pengambilan keputusan, perencanaan, dan evaluasi kinerja pemerintah daerah.

1Inisial

Tidak ada kebijakan aktualitas. Data diperbarui secara ad hoc tanpa jadwal yang pasti.

2Terdokumentasi

Ada jadwal pemutakhiran internal namun belum dipublikasikan ke pengguna data.

3Terdefinisi

SOP pemutakhiran terdokumentasi. Frekuensi (bulanan/tahunan) dikomunikasikan ke publik.

4Terkelola

Pemutakhiran tepat waktu dengan SLA, dipantau via dashboard, ada notifikasi keterlambatan.

5Optimal

Pemutakhiran prediktif near real-time, integrasi sistem dan otomasi, analisis gap aktualitas.

Cara Pengukuran

Persentase dataset yang diperbarui sesuai jadwal yang dijanjikan (jumlah dataset tepat waktu / total dataset aktif) × 100%; median lag time antara akhir periode referensi dan tanggal publikasi di Portal Open Data; jumlah dataset prioritas dengan dimensi_akhir sama dengan tahun berjalan.

2
Tingkat Kematangan Pemantauan Ketepatan Waktu Diseminasi
Ketepatan Waktu · Diseminasi
Definisi

Kemampuan memantau dan mengevaluasi keterpatuhan jadwal publikasi data statistik sektoral sesuai komitmen yang ditetapkan dalam Kalender Statistik Sektoral (KSS).

Tujuan

Membangun kepercayaan pengguna data melalui kepastian waktu rilis, sehingga perencanaan dan evaluasi berbasis data dapat dijadwalkan dengan andal oleh seluruh pemangku kepentingan.

1Inisial

Tidak ada kalender publikasi. Rilis data terjadi tanpa komitmen waktu.

2Terdokumentasi

Ada kalender publikasi internal namun tidak dipublikasikan; pemantauan manual.

3Terdefinisi

Kalender Statistik Sektoral dipublikasikan; ada pencatatan ketertinggalan rilis.

4Terkelola

Pemantauan via dashboard real-time; eskalasi otomatis jika rilis terlambat.

5Optimal

Otomasi pemantauan dengan alert publik dan mekanisme kompensasi (penjelasan keterlambatan).

Cara Pengukuran

Persentase rilis tepat waktu (rilis on-schedule / total rilis terkomitmen) × 100%; rata-rata hari keterlambatan; jumlah rilis terlambat per periode pelaporan; keberadaan dokumen Kalender Statistik Sektoral yang dipublikasikan di portal.

3
Tingkat Kematangan Ketersediaan Data untuk Pengguna Data
Ketersediaan · Cakupan Data
Definisi

Tingkat kelengkapan cakupan data yang tersedia bagi pengguna, dilihat dari sisi periode (time series), wilayah (spasial), dan variabel (dimensional) yang dapat diakses publik.

Tujuan

Memastikan pengguna dapat mengakses data yang cukup untuk analisis tren, komparasi antarwilayah, dan pengambilan keputusan berbasis bukti.

1Inisial

Sebagian besar variabel dan periode tidak tersedia; data fragmentaris.

2Terdokumentasi

Tersedia untuk wilayah administratif tinggi (kota) dan beberapa periode.

3Terdefinisi

Tersedia untuk seluruh kelurahan/kecamatan dan periode beberapa tahun terakhir.

4Terkelola

Cakupan periode ≥ 5 tahun dengan time series konsisten; variabel lengkap.

5Optimal

Cakupan multi-dimensi (temporal, spasial, demografis) dengan metadata lengkap dan data turunan.

Cara Pengukuran

Persentase variabel terisi (variabel tersedia / variabel terencana) × 100%; panjang time series rata-rata (dimensi_akhir − dimensi_awal); cakupan wilayah administratif (jumlah kelurahan/kecamatan tercakup / total × 100%); completeness ratio per dataset.

4
Tingkat Kematangan Akses Media Penyebarluasan Data
Akses · Diseminasi
Definisi

Variasi dan kualitas saluran distribusi yang digunakan untuk menyebarluaskan data ke pengguna, mencakup portal open data, API publik, dashboard tematik, dan saluran publikasi lainnya.

Tujuan

Memperluas jangkauan dan menurunkan barrier akses data bagi berbagai segmen pengguna (ASN, akademisi, media, masyarakat, dan sistem aplikasi).

1Inisial

Distribusi melalui dokumen cetak/PDF statis yang diminta manual.

2Terdokumentasi

Ditambah distribusi melalui situs web OPD dengan unduhan manual.

3Terdefinisi

Portal open data khusus dengan API publik (contoh: opendata.bandung.go.id).

4Terkelola

API terdokumentasi machine-readable, plus integrasi ke dashboard tematik.

5Optimal

Multi-channel (portal, API, dashboard, mobile, embed widget) dengan versioning API dan SDMX.

Cara Pengukuran

Jumlah saluran diseminasi aktif; kelengkapan dokumentasi API (Swagger/OpenAPI); jumlah format yang didukung per dataset; jumlah unduhan dan panggilan API per bulan (via analytics portal).

Tingkat Kematangan Penyediaan Format Data
Format · Standar Data
Definisi

Variasi format file yang disediakan untuk memenuhi kebutuhan konsumsi data yang beragam, baik untuk pembacaan oleh manusia (human-readable) maupun olahan mesin (machine-readable).

Tujuan

Mendukung reuse data dengan format yang sesuai standar interoperabilitas dan kebutuhan teknis pengguna (analisis, visualisasi, integrasi sistem).

1Inisial

Hanya PDF/Word (non-machine-readable), sering berupa hasil pindai.

2Terdokumentasi

Tambahan Excel/CSV dengan struktur belum konsisten.

3Terdefinisi

CSV + JSON + Excel standar dengan encoding UTF-8 dan header konsisten.

4Terkelola

Ditambah format geospasial (GeoJSON, Shapefile) untuk data berlokasi; API JSON.

5Optimal

Multi-format sesuai standar internasional (CSV, JSON, Parquet, SDMX, RDF) dengan versioning.

Cara Pengukuran

Jumlah format per dataset (minimal 3 format machine-readable); kepatuhan standar encoding UTF-8; konsistensi header kolom antar periode; persentase dataset dengan format geospasial untuk data berlokasi.

6
Tingkat Kematangan Keterbandingan Data
Keterbandingan · Komparabilitas
Definisi

Kemampuan data untuk dibandingkan antar waktu (temporal), antar wilayah (spasial), dan antar sumber menggunakan konsep, definisi, klasifikasi, dan unit pengukuran yang konsisten.

Tujuan

Mendukung analisis komparatif yang valid antar periode dan antar daerah, termasuk benchmarking kinerja antar OPD dan antar kota.

1Inisial

Tidak ada standar klasifikasi; definisi variabel berubah antar periode.

2Terdokumentasi

Ada upaya konsistensi namun belum terdokumentasi dalam metadata.

3Terdefinisi

Klasifikasi mengikuti standar nasional (SBI, KLU, KBKI); metadata variabel tersedia.

4Terkelola

Time series konsisten ≥ 5 tahun; cross-region comparable; ada dokumen metodologi.

5Optimal

Benchmarking dengan kota/negara lain; integrasi standar internasional; ada panel data.

Cara Pengukuran

Konsistensi definisi variabel antar periode (persentase variabel dengan definisi tidak berubah); ketersediaan dokumen metadata (DDI/SDMX); jumlah dataset yang dapat dibandingkan dengan data BPS kota/kabupaten lain.

Tingkat Kematangan Konsistensi Data
Konsistensi · Rekonsiliasi
Definisi

Kesesuaian data antar sumber, antar rilis, dan dengan statistik resmi (terutama BPS), ditambah rekonsiliasi yang sistematis untuk mereduksi konflik data antar OPD penghasil.

Tujuan

Menghindari kontradiksi data yang dapat membingungkan pengguna dan menurunkan kredibilitas statistik sektoral, serta membangun single source of truth.

1Inisial

Sering terjadi konflik antar dataset dan tidak ada resolusi.

2Terdokumentasi

Konflik teridentifikasi namun tidak ditindaklanjuti secara formal.

3Terdefinisi

Rekonsiliasi berkala antar OPD dan BPS; ada walidata yang bertanggung jawab.

4Terkelola

Sistem rekonsiliasi otomatis; ada data master referensi tunggal.

5Optimal

Single source of truth dengan audit trail; selisih < threshold yang ditetapkan.

Cara Pengukuran

Jumlah konflik data teridentifikasi per periode (data OPD vs data BPS untuk variabel yang sama); persentase rekonsiliasi sukses; deviasi rata-rata dari data referensi BPS; keberadaan data master referensi tunggal.

Dimensi Pemanfaatan Data menilai sejauh mana data statistik dasar (BPS) dan statistik sektoral (OPD) digunakan dalam siklus perencanaan, monitoring, evaluasi, dan penyusunan kebijakan di Kota Bandung, serta tingkat literasi data di lingkungan pemerintah dan masyarakat. Tingkat Kematangan Penggunaan Data Statistik Dasar untuk Perencanaan, Monitoring, dan Evaluasi, dan atau Penyusunan Kebijakan
Statistik Dasar · BPS
Definisi

Tingkat penggunaan data statistik dasar (kependudukan, sosial, ekonomi dasar) yang dihasilkan BPS dalam dokumen perencanaan dan kebijakan daerah seperti RPJMD, RKPD, Renstra, dan dokumen kebijakan lainnya.

Tujuan

Memastikan kebijakan dan perencanaan pembangunan daerah berbasis data terverifikasi resmi yang memiliki kredibilitas metodologi dan keterbandingan nasional.

1Inisial

Tidak ada referensi data BPS dalam dokumen perencanaan daerah.

2Terdokumentasi

Data BPS disebut namun tidak dianalisis (ornamental) dalam dokumen.

3Terdefinisi

Digunakan sebagai baseline indikator kinerja RPJMD dan Renstra OPD.

4Terkelola

Digunakan untuk target-setting dan evaluasi kinerja secara sistematis berkala.

5Optimal

Menggerakkan model kebijakan (policy modeling), forecasting, dan adaptive planning.

Cara Pengukuran

Jumlah dokumen perencanaan (RPJMD, RKPD, Renstra) yang mengutip data BPS sebagai baseline; persentase Indikator Kinerja Utama (IKU) yang menggunakan data BPS; keberadaan analisis dampak berbasis data BPS; integrasi dalam sistem e-planning daerah.

2
Tingkat Kematangan Penggunaan Data Statistik Sektoral untuk Perencanaan, Monitoring, dan Evaluasi, dan atau Penyusunan Kebijakan
Statistik Sektoral · OPD
Definisi

Tingkat penggunaan data statistik sektoral yang dihasilkan OPD penghasil data dalam dokumen perencanaan sektoral, monitoring kinerja, dan penyusunan kebijakan teknis bidang.

Tujuan

Memastikan kebijakan sektoral berbasis data lapangan yang akurat, terkini, dan relevan dengan kebutuhan operasional bidang (kesehatan, pendidikan, ketahanan pangan, dll).

1Inisial

Tidak ada data sektoral dirujuk dalam dokumen OPD penghasil.

2Terdokumentasi

Data sektoral disebut namun tidak dianalisis dalam Renstra.

3Terdefinisi

Digunakan dalam Renstra OPD dan laporan kinerja triwulanan.

4Terkelola

Dipakai untuk target pencapaian dan evaluasi triwulanan dengan dashboard.

5Optimal

Dipakai untuk model prediksi, intervention design, dan adaptive policy.

Cara Pengukuran

Persentase OPD yang mengutip datanya sendiri dalam Renstra (OPD yang mengutip / total OPD penghasil × 100%); jumlah dokumen kebijakan dengan analisis sektoral berbasis data; jumlah kebijakan baru yang didukung analisis data sektoral.

Tingkat Kematangan Sosialisasi dan Literasi Data Statistik
Sosialisasi · Literasi Data
Definisi

Tingkat upaya sosialisasi data statistik dan literasi statistik kepada pemangku kepentingan (ASN, media, akademisi) dan masyarakat luas, mencakup pelatihan, infografis, dan program literasi data.

Tujuan

Meningkatkan kapasitas konsumsi, interpretasi, dan pemanfaatan data yang benar oleh seluruh pemangku kepentingan, sehingga data tidak hanya tersedia tetapi juga dimengerti dan digunakan.

1Inisial

Tidak ada kegiatan sosialisasi data statistik sektoral.

2Terdokumentasi

Sosialisasi insidental tanpa materi terstruktur dan dokumentasi.

3Terdefinisi

Program sosialisasi tahunan dengan modul dan target peserta.

4Terkelola

Pelatihan reguler multi-tier (ASN, media, masyarakat); infografis dan story-telling.

5Optimal

Literasi data tertanam dalam kurikulum; ada data academy; komunitas data aktif.

Cara Pengukuran

Jumlah peserta pelatihan data per tahun (ASN + non-ASN); frekuensi sosialisasi tahunan; ketersediaan materi edukasi publik (infografis, video, modul); indeks literasi data masyarakat (via survei sampel); jumlah publikasi infografis per OPD.

Standar Data Statistik
Peraturan BPS 10/2023 · 5 Komponen SDS
Definisi

Berdasarkan Perpres 39/2019 tentang Satu Data Indonesia, Standar Data adalah standar yang mendasari Data tertentu. Lebih spesifik, Peraturan BPS Nomor 10 Tahun 2023 tentang Standar Data Statistik mendefinisikan Standar Data Statistik (SDS) sebagai konsep, definisi, klasifikasi, ukuran, dan satuan yang dibakukan untuk menghasilkan data statistik yang sesuai dengan kaidah statistik dan dapat dipertanggungjawabkan.

Dasar Hukum & Regulasi
  • Perpres 39/2019 tentang Satu Data Indonesia — Pasal 13 menetapkan tugas Pembina Data (BPS): menetapkan Standar Data, format Metadata, dan Interoperabilitas Data
  • Peraturan BPS Nomor 10 Tahun 2023 tentang Standar Data Statistik — menggantikan Peraturan BPS Nomor 4 Tahun 2021, ditetapkan 20 November 2023 oleh Kepala BPS Amalia Adininggar Widyasanti
  • SNI 8099:2021 tentang Statistik Sektoral — Standar Nasional Indonesia
  • UU 6/2023 tentang Cipta Kerja — kerangka kebijakan terkait pengelolaan data
5 Komponen Standar Data Statistik (Peraturan BPS 10/2023)
  • Konsep — gagasan atau ide yang mendasari suatu data statistik (misal: konsep penduduk, pengangguran, inflasi)
  • Definisi — penjelasan resmi dan baku tentang makna konsep sesuai kaidah statistik
  • Klasifikasi — penggolongan data secara sistematis ke dalam kelompok/kategori berdasarkan kriteria yang ditetapkan Pembina Data Statistik
  • Ukuran — cara pengukuran atau kuantifikasi variabel (misal: jumlah absolut, persentase, rasio, indeks)
  • Satuan — unit pengukuran yang digunakan (orang, ton, hektar, Rupiah, kWh, dll.)
Klasifikasi Baku BPS (Komponen Klasifikasi)
  • KBLI (Klasifikasi Baku Lapangan Usaha Indonesia) — mengikuti ISIC Rev. 4 PBB, dikelola BPS untuk statistik ekonomi & ketenagakerjaan
  • KBKI (Klasifikasi Baku Komoditas Indonesia) — klasifikasi komoditas untuk statistik perdagangan, pertanian, dan industri
  • SKU (Standar Klasifikasi Usaha) — klasifikasi unit statistik usaha
  • Kode Wilayah Administratif — mengikuti Permendagri (Kota Bandung: 32.73 / 3073)
Penerapan di Kota Bandung

Setiap OPD penghasil data statistik sektoral di Kota Bandung wajib mengacu pada Standar Data Statistik Nasional sesuai Peraturan BPS Nomor 10 Tahun 2023. Klasifikasi usaha mengikuti KBLI, komoditas mengikuti KBKI, kode wilayah mengikuti Permendagri. BPS Kota Bandung sebagai Pembina Data melakukan pembinaan teknis untuk memastikan dataset yang dipublikasikan di Portal Open Data Bandung memenuhi 5 komponen SDS: konsep, definisi, klasifikasi, ukuran, dan satuan.

2
Metadata Statistik
Peraturan BPS 5/2020 · 3 Jenis Metadata
Definisi

Berdasarkan Perpres 39/2019 tentang Satu Data Indonesia, Metadata adalah informasi dalam bentuk struktur dan format yang baku untuk menggambarkan Data. Data yang dihasilkan oleh Produsen Data wajib dilengkapi dengan Metadata yang informasinya mengikuti struktur yang baku dan dapat dibaca oleh mesin. Metadata menjawab pertanyaan: apa, siapa, kapan, di mana, bagaimana, dan seberapa dapat dipercaya.

Dasar Hukum & Regulasi
  • Perpres 39/2019 tentang Satu Data Indonesia — mendefinisikan metadata dan mewajibkan setiap data yang dihasilkan dilengkapi metadata
  • Peraturan BPS Nomor 5 Tahun 2020 tentang Petunjuk Teknis Metadata Statistik — pedoman pengelolaan metadata statistik bagi instansi pusat dan daerah
  • Pasal 13 Perpres 39/2019 — Pembina Data (BPS) menetapkan format metadata
  • Keputusan Kepala BPS Nomor 5 Tahun 2000 — Sistem Statistik Nasional dengan aspek KISS (Koordinasi, Integrasi, Sinkronisasi, Standardisasi)
3 Jenis Metadata Statistik (Peraturan BPS 5/2020)
  • Metadata Kegiatan — menggambarkan kegiatan statistik: nama kegiatan, tujuan, sumber data, frekuensi, periode referensi, metode pengumpulan, daftar variabel & indikator
  • Metadata Variabel — menggambarkan variabel dalam kegiatan statistik: definisi variabel, satuan, tipe data, referensi klasifikasi, nilai valid
  • Metadata Indikator — menggambarkan indikator turunan: definisi indikator, formula perhitungan, interpretasi, sumber data, batasan metodologi

Hierarki pengisian: Metadata Variabel dan Metadata Indikator hanya dapat diinput setelah Metadata Kegiatan diinput terlebih dahulu dalam SIRUSA.

Sistem Pengelolaan Metadata BPS
  • SIRUSA (Sistem Informasi Rujukan Statistik) — sistem metadata BPS sebagai rujukan nasional untuk metadata kegiatan, variabel, dan indikator
  • KISS Principle — Koordinasi, Integrasi, Sinkronisasi, Standardisasi (Keputusan Kepala BPS 5/2000)
  • Pembina Data (BPS) melakukan koordinasi KISS dengan seluruh K/L/D/I penghasil statistik
  • Format metadata machine-readable — sesuai amanat Perpres 39/2019 agar dapat dibaca sistem
Penerapan di Portal Open Data Bandung

Setiap dataset di Portal Open Data Bandung dilengkapi metadata yang sejalan dengan kerangka Peraturan BPS Nomor 5 Tahun 2020, mencakup: nama dataset (judul kegiatan), organisasi penghasil (walidata), periode referensi (dimensi_dataset_awal s/d dimensi_dataset_akhir), status data tetap/sementara, priority level, format file, dan frekuensi pemutakhiran. BPS Kota Bandung sebagai Pembina Data melakukan pembinaan penyusunan metadata statistik sektoral bagi seluruh OPD Kota Bandung.

Interoperabilitas
Teknis · Semantik · Organisasional
Definisi

Interoperabilitas adalah kemampuan dua atau lebih sistem/organisasi untuk bertukar dan menggunakan data secara konsisten dan efektif. Mengacu pada European Interoperability Framework (EIF), interoperabilitas mencakup empat level: teknis, semantik, organisasional, dan hukum.

Empat Level Interoperabilitas (EIF)
  • Teknis: kesepakatan format file (CSV, JSON), protokol (HTTP, REST), API (OpenAPI spec), encoding (UTF-8)
  • Semantik: kesepakatan makna data — klasifikasi, kode referensi, kamus data, ontology, mapping antar konsep
  • Organisasional: kesepakatan proses bisnis antar organisasi, peran walidata, SLA, koordinasi antar OPD
  • Hukum: kesepakatan perjanjian data sharing, lisensi data (CC-BY 4.0, ODbL), kebijakan tata kelola, UU PDP
Komponen Pendukung
  • API publik (REST, GraphQL, SOAP) dengan dokumentasi OpenAPI/Swagger
  • Master Data Management (MDM) — data referensi tunggal
  • Data Dictionary / Data Catalog — kamus data terstandardisasi
  • Identifier unik: NIK, NPSN, kode wilayah, kode POA
  • Integrasi sistem: ETL, message queue (Kafka, RabbitMQ), webhook
Penerapan di Kota Bandung

Portal Open Data Bandung sebagai single front-end diseminasi. Integrasi sistem: SIPKD (keuangan), SIMRAL (SDA), SIAP (pendidikan), DCK (Adminduk). API publik tersedia untuk dataset open data. Walidata tiap OPD sebagai single point of responsibility. BPS Kota Bandung sebagai pembina menyusun standar interoperabilitas statistik sektoral.

GSBPM — Generic Statistical Business Process Model
UNECE · Siklus Produksi Statistik
Definisi

GSBPM adalah model proses bisnis statistik generik yang dikembangkan UNECE (United Nations Economic Commission for Europe) yang menjelaskan seluruh siklus produksi statistik dari identifikasi kebutuhan hingga evaluasi. GSBPM menjadi acuan standar internasional untuk tata kelola produksi statistik dan diadopsi oleh BPS, Eurostat, OECD, dan badan statistik nasional lainnya.

8 Fase Utama GSBPM
1
Specify Needs

Identifikasi pengguna, scope, tujuan, dan indikator yang dibutuhkan.

2
Design

Metodologi, sampling, instrumen, definisi variabel, klasifikasi.

3
Build

Pengembangan instrumen pengumpulan, sistem, prosedur kerja.

4
Collect

Pengumpulan data: survei, data administrasi, sensor, crowdsourcing.

5
Process

Cleaning, coding, editing, imputasi, validasi, derivasi variabel.

6
Analyse

Agregasi, estimasi, analisis statistik, quality control, interpretasi.

7
Disseminate

Publikasi, portal open data, API, infografis, publikasi resmi.

8
Evaluate

Review proses, kualitas output, feedback ke fase 1 (Specify Needs).

Fase Pendukung (Cross-cutting)
  • Quality Management — manajemen mutu lintas fase
  • Metadata Management — pengelolaan metadata sepanjang siklus
  • Data Management — storage, retention, backup
  • Process Management — workflow, monitoring, audit
  • Provider Management — hubungan dengan sumber data
  • Statistical Framework Management — kerangka metodologi
  • Subject Matter Management — keahlian domain (kesehatan, pendidikan, dll)
  • Customer/Consumer Management — hubungan dengan pengguna data
Penerapan di Kota Bandung

Setiap OPD penghasil data statistik sektoral mengikuti siklus GSBPM. Walidata bertanggung jawab pada fase Collect → Process → Disseminate. BPS Kota Bandung sebagai pembina menyusun standar pada fase Design → Analyse → Evaluate. Penerapan GSBPM memastikan seluruh dataset yang masuk ke Portal Open Data sudah melalui siklus produksi yang terdokumentasi, dapat ditelusuri (traceable), dan memenuhi standar kualitas.

Definisi & Karakteristik (3V+2V)

Big Data adalah data berukuran besar yang tidak dapat diolah dengan metode tradisional. Karakteristik utama 3V: Volume (ukuran besar, TB-PB), Velocity (kecepatan tinggi, near real-time), dan Variety (format beragam — terstruktur, semi, tak terstruktur). Sering ditambah 2V: Veracity (keakuratan/kepercayaan) dan Value (nilai manfaat).

Sumber Big Data
  • Mobile Positioning Data (MPD): data lokasi ponsel dari operator seluler
  • Citra satelit & remote sensing: Landsat, Sentinel-2, MODIS, VIIRS
  • Social media data: Twitter/X, Instagram, Facebook public posts
  • Sensor IoT: traffic, kualitas udara, cuaca, smart meter
  • Web scraping: harga komoditas dari e-commerce, berita
  • Transaksi digital: e-wallet, e-commerce, payment gateway
  • Call Detail Records (CDR): dari operator telekomunikasi
  • CCTV & video analytics: pengenalan plat nomor, hitung kendaraan
Contoh Pemanfaatan
  • Statistik Mobilitas Penduduk (BPS × Telkomsel): MPD untuk estimasi pergerakan penduduk harian antar daerah, penduduk sementara, dan arah migrasi.
  • Kerawanan Pangan & Luas Panen (BPS KSA): citra satelit Sentinel-2 untuk estimasi luas panen padi dan deteksi kerawanan pangan.
  • Pemantauan Kemacetan Lalu Lintas: data GPS dari aplikasi ride-hailing dan CCTV ATCS untuk traffic real-time di Kota Bandung.
  • Deteksi Titik Panas (Hotspot): data satelit MODIS/VIIRS untuk deteksi kebakaran hutan/lahan (BPBD).
  • Indeks Harga Konsumen (IHK) Pintar: web scraping harga komoditas dari e-commerce untuk verifikasi dan pengembangan IHK real-time.
  • Sentimen Publik & Layanan: analisis media sosial untuk mengukur persepsi publik terhadap layanan (Bagian Humas Kota Bandung).
  • Pemantauan Kualitas Udara: sensor IoT pemantauan PM2.5/PM10 di sejumlah titik Kota Bandung (DLH).
  • Prediksi Bencana & Cuaca: kombinasi data BMKG, sensor curah hujan, dan citra satelit untuk early warning system banjir (BPBD).
Tantangan & Framework
  • Privacy & Data Protection: kepatuhan pada UU 27/2022 Pelindungan Data Pribadi
  • Bias representativitas: digital divide, akses tidak merata
  • Kualitas data: validasi, cleaning, standarisasi data non-tradisional
  • Kapasitas teknis: skill data science, infrastruktur komputasi (cloud, HPC)
  • Framework pendukung: UNSC Big Data Working Group, G20 Data Gaps Initiative, BPS Pusat Penelitian Big Data
Dimensi Potensi Big Data mengidentifikasi sumber data non-tradisional berukuran besar yang dapat dimanfaatkan untuk menghasilkan statistik sektoral dan mendukung pengambilan keputuran di Kota Bandung. Mencakup inventarisasi sumber (CCTV lintas OPD, sensor IoT, citra satelit, MPD, transaksi digital), kategori data yang bisa diekstrak, roadmap implementasi 5 fase 5 tahun, studi kasus pemanfaatan CCTV Kota Bandung, serta keterkaitan dengan dataset eksisting di Portal Open Data.

Konteks & Keterbatasan Penyimpanan CCTV

Penyimpanan rekaman video CCTV memiliki keterbatasan waktu (retensi standar 7-30 hari) dan volume (1 CCTV 1080p ≈ 20-60 GB/hari). Untuk kepatuhan UU 27/2022 PDP, retensi raw video harus diminimalkan. Solusi arsitektur: ekstrak metadata/statistik dari video secara real-time → simpan jangka panjang (5+ tahun) di PostgreSQL/InfluxDB. Raw video 7-30 hari; statistik & event 5+ tahun; ANPR aggregated (tanpa plat lengkap) untuk data publik.

Dapat dilakukan dalam 1-2 bulan menggunakan data CCTV ATCS eksisting, tanpa menunggu pipeline AI penuh. CCTV Perbatasan & Analisis Mobilitas
Commuter · Wisatawan Nusantara · BBM
Inventarisasi CCTV Perbatasan Kota Bandung

CCTV di titik perbatasan Kota Bandung untuk monitoring arus masuk-keluar kendaraan:

  • Barat: Padalarang + gerbang tol Cipularang (arah Jakarta)
  • Timur: Cileunyi + gerbang tol Padaleunyi (arah Garut/Tasik)
  • Selatan: Soreang, Pasir Jambu
  • Utara: Lembang
  • Batas Cimahi: beberapa titik di perbatasan barat
  • Titik strategis dalam kota: Jl. Soekarno-Hatta, Jl. AH Nasution, Jl. Pasteur

Setiap titik perbatasan perlu dilengkapi ANPR (Automatic Number Plate Recognition) untuk identifikasi asal kendaraan via plat nomor.

Pola Mobilitas Commuter (Pagi vs Sore)

Pola arah kendaraan di CCTV perbatasan memperlihatkan pola commuter jelas pada hari kerja:

PeriodeArah DominanIndikasi
Pagi 06:00-09:00Masuk BandungCommuter berangkat kerja dari Cimahi, Kab. Bandung, Sumedang
Siang 09:00-16:00BerimbangAktivitas distribusi & kunjungan
Sore 16:00-19:00Keluar BandungCommuter pulang kerja
Malam 19:00-06:00RendahLogistik & aktivitas malam

Analisis: Asimetri morning-in vs evening-out mengindikasikan populasi commuter. Selisih volume pagi vs sore mengestimasi net flow harian. Plat D (Bandung) vs non-D membedakan resident vs commuter.

Wisatawan Nusantara via ANPR

Identifikasi plat nomor dari kota lain sebagai indikator wisatawan nusantara (konsep BPS: perjalanan domestik untuk tujuan wisata, di luar lingkungan biasa):

  • Plat B (DKI Jakarta) — wisatawan Jakarta, mayoritas weekend & long weekend
  • Plat E (Cirebon), F (Bogor/Sukabumi), T (Purwakarta/Karawang) — wisatawan regional Jabar
  • Plat lain (A, AA, AB, AD, dll.) — wisatawan luar Jabar
  • Plat D (Bandung) — resident & regular commuter (baseline)

Pola wisatawan: peak pada Sabtu-Minggu, long weekend, dan musim libur Lebaran/Natal/Tahun Baru. Cross-reference dengan dataset "Jumlah Wisatawan Mancanegara dan Domestik" (Dinas Kebudayaan dan Pariwisata) untuk validasi & gap-filling statistik pariwisata BPS.

Kendaraan Masuk-Keluar & Analisis Kebutuhan BBM

Hitung volume kendaraan masuk vs keluar per hari dari CCTV perbatasan, lalu estimasi kebutuhan BBM berdasarkan klasifikasi & jarak tempuh rata-rata:

Jenis KendaraanKonsumsi BBMRata-rata JarakBBM/Hari
Motor~3 L/100 km15 km~0.45 L
Mobil penumpang~8 L/100 km20 km~1.6 L
Bus~25 L/100 km30 km~7.5 L
Truk~30 L/100 km25 km~7.5 L

Formula: Total BBM/hari = Σ (count_per_jenis × BBM_per_jenis_per_hari). Output berguna untuk: distribusi BBM Pertamina, penempatan SPBU, kebijakan subsidi BBM, estimasi Pendapatan Asli Daerah dari PBBKB (Pajak Bahan Bakar Kendaraan Bermotor), dan estimasi emisi transportasi Kota Bandung.

Studi Perbandingan Hari Kerja vs Hari Libur

Quick win dalam 1-2 bulan menggunakan data CCTV perbatasan eksisting:

  • Hari kerja: peak asimetris (in pagi, out sore), dominasi plat D, volume regular
  • Hari libur biasa (Sab-Min): peak simetris tengah hari (10-14), mix plat D + B + E + F
  • Long weekend: volume masuk Jumat sore-Minggu tinggi (wisatawan nusantara), keluar Minggu sore-Senin pagi
  • Libur Lebaran: arus balik massive dari/ke Jakarta (plat B dominan di Jl. Soekarno-Hatta & Cipularang)

Dataset baru untuk Portal Open Data: "Volume Kendaraan Perbatasan per Jam", "Estimasi Commuter Harian", "Estimasi Wisatawan Nusantara via ANPR", "Estimasi Kebutuhan BBM Harian Kota Bandung".

Fase 1-2 — Specify Needs & Design
Identifikasi Kebutuhan · Metodologi · SDS
Fase 1: Specify Needs (Tentukan Kebutuhan)

Identifikasi kebutuhan statistik dari stakeholder Kota Bandung:

  • Dinas Perhubungan — volume lalu lintas, klasifikasi kendaraan, kecepatan rata-rata
  • Bappeda — indikator mobilitas untuk perencanaan tata ruang
  • BPS Kota Bandung — wisatawan nusantara, commuter, validasi statistik
  • Pusdatin Diskominfo — data untuk Command Center & smart city
  • Dinas Pariwisata — pengunjung kawasan wisata, wisatawan domestik
  • DLH — emisi transportasi, kualitas udara
  • Bapenda — estimasi PBBKB untuk Pendapatan Asli Daerah

Output Fase 1: Dokumen Kebutuhan Statistik + daftar indikator target dengan prioritas.

Fase 2: Design (Desain sesuai SDS)

Desain metodologi CCTV-based statistics sesuai 5 Komponen Standar Data Statistik (Peraturan BPS 10/2023):

  • Konsep: "commuter", "wisatawan nusantara", "volume lalu lintas", "kebutuhan BBM"
  • Definisi: formal sesuai kaidah statistik (mis. wisatawan nusantara = perjalanan domestik di luar lingkungan biasa untuk tujuan wisata)
  • Klasifikasi: motor/mobil penumpang/bus/truk; plat region (D=Bandung, B=Jakarta, E=Cirebon, F=Bogor, T=Purwakarta); hari kerja/libur
  • Ukuran: count absolut, rate per jam, persentase, rasio masuk-keluar
  • Satuan: kendaraan/jam, orang/hari, liter BBM/hari

Sampling: pemilihan titik CCTV representatif (perbatasan + simpang ATCS + kawasan wisata). Metadata design: template Metadata Kegiatan sesuai Peraturan BPS 5/2020 untuk SIRUSA.

Output Fase 1-2
  • Dokumen Kebutuhan Statistik CCTV (stakeholder + indikator target)
  • Dokumen Metodologi CCTV-based Statistics
  • Template Metadata Kegiatan (SIRUSA-ready)
  • Peta titik CCTV representatif untuk sampling
  • Definisi variabel & klasifikasi sesuai SDS Peraturan BPS 10/2023

Fase 4: Collect (Kumpulkan Data)

Pengumpulan data real-time dari CCTV lintas OPD:

  • Real-time video streaming dari CCTV ATCS, perbatasan, BPBD, Satpol PP
  • Object detection (YOLOv8) — counting kendaraan per kategori (motor/mobil/bus/truk)
  • ANPR capture — plat nomor identification dengan privacy blurring untuk data publik (UU 27/2022 PDP)
  • Crowd density estimation di kawasan ramai (Braga, BCH, Tegalega)
  • Incident detection — anomaly detection (kecelakaan, perkelahian)
  • Quality at source — kalibrasi CCTV, validasi capture, redundancy

Output Fase 4: Raw data — events, counts kendaraan per jam, ANPR aggregated (tanpa plat lengkap), incident logs.

Quality Checkpoint Fase 3-4
  • Kalibrasi CCTV berkala (optical alignment, focus, low-light performance)
  • Validasi ANPR vs manual count (sample audit)
  • Uptime monitoring per CCTV (target > 95%)
  • Retention policy: raw video 7-30 hari, events & statistik 5+ tahun
4
Fase 5-6 — Process & Analyse
Cleaning · Estimasi · QC vs BPS
Fase 5: Process (Olah Data)

Transformasi raw events menjadi data terstruktur siap analisis:

  • Data cleaning — filter noise, outliers, sensor error, double counting
  • Validation — cross-check dengan data referensi (BPS, manual count ATCS)
  • Imputasi — isi missing data dengan interpolasi temporal (jam sebelumnya)
  • Klasifikasi — kategorisasi kendaraan, plat region mapping (D=Bandung, B=Jakarta, dll.)
  • Agregasi — per jam, harian, mingguan, bulanan, per simpang, per kawasan
  • Derivasi variabel — commuter (selisih pagi-sore), wisatawan (plat non-D), estimasi BBM

Output Fase 5: Clean structured data — siap analisis + input Metadata Variabel ke SIRUSA.

Fase 6: Analyse (Analisis Statistik)

Hitung statistik agregat & validasi kualitas:

  • Statistik agregat — mean, median, percentil, distribusi volume kendaraan
  • Estimasi — total commuter harian, total wisatawan, total BBM demand
  • Time series analysis — tren harian/mingguan, seasonal pattern (hari kerja vs libur)
  • Cross-validation vs data BPS (wisatawan nusantara vs data Disbudpar)
  • Outlier detection — anomaly di hari tertentu (event khusus, libur nasional)
  • Bias correction — koreksi systematic bias (mis. undercount motor)
  • Interpretation — analisis pola, narrative untuk publikasi

Output Fase 6: Statistik siap publikasi + Quality Report + input Metadata Indikator ke SIRUSA.

Overview Pipeline GSBPM Shopee Live
5V Big Data · 8 Fase · E-Commerce
Definisi & Karakteristik 5V Shopee Live

Shopee Live adalah fitur live commerce di aplikasi Shopee yang memungkinkan seller melakukan streaming video langsung sambil menjual produk. Data transaksi Shopee Live termasuk Big Data karena memenuhi karakteristik 5V:

  • Volume — jutaan transaksi/hari di Indonesia, terutama saat mega campaign (11.11, 12.12, Harbolnas)
  • Velocity — transaksi terjadi real-time selama sesi live streaming (detik-per-detik)
  • Variety — video stream, chat, transaksi, pembayaran, fulfillment, engagement (likes, shares, comments)
  • Veracity — anti-fraud detection, validasi transaksi, return/refund data
  • Value — indikator ekonomi digital real-time, konsumsi MSME, performa seller, regional demand

Fase 1: Specify Needs (Tentukan Kebutuhan)

Identifikasi kebutuhan statistik e-commerce dari stakeholder Kota Bandung:

Output Fase 1: Dokumen Kebutuhan Statistik E-Commerce + daftar indikator target dengan prioritas.

Fase 2: Design (Desain sesuai SDS)

Desain metodologi e-commerce statistics sesuai 5 Komponen Standar Data Statistik (Peraturan BPS 10/2023):

  • Konsep: "GMV" (Gross Merchandise Value), "AOV" (Average Order Value), "seller", "buyer", "conversion rate", "live engagement"
  • Definisi: formal sesuai BPS & kaidah statistik (mis. GMV = nilai total transaksi sebelum diskon & pajak)
  • Klasifikasi: KBLI 4791 (perdagangan e-commerce), KBKI untuk kategori produk (fashion, F&B, beauty, elektronik, rumah), SKU produk
  • Ukuran: GMV (Rp), jumlah transaksi, jumlah seller, jumlah buyer, AOV, conversion rate (%), engagement rate
  • Satuan: Rupiah (Rp), transaksi, seller, buyer, %

Sampling: filter transaksi seller Bandung (berdasarkan kode pos / alamat seller). Metadata design: template Metadata Kegiatan sesuai Peraturan BPS 5/2020 untuk SIRUSA.

Fase 3-4 — Build & Collect
MoU Shopee · API · Real-time
Fase 3: Build (Bangun Infrastruktur)
  • MoU Pemkot Bandung × Shopee — perjanjian data sharing dengan anonimisasi data pribadi
  • Shopee Open Platform API — integrasi Seller API, Order API, Live Stream API

  • Standar PMSE — kepatuhan PP 19/2023 & Permendag 31/2023

Output Fase 3: Integrasi Shopee API operasional + data warehouse siap ingest real-time.

Fase 4: Collect (Kumpulkan Data)

Pengumpulan data real-time dari Shopee Live:

  • Real-time transaction events — order placement, payment confirmation, fulfillment status
  • Live stream metadata — viewer count, watch time, likes, shares, comments, product clicks
  • Seller data (Bandung-based) — profil seller, rating, fulfillment rate, return rate
  • Product categorization — kategori utama, sub-kategori, SKU, harga, diskon
  • Payment data — ShopeePay, COD, bank transfer, BNPL (Buy Now Pay Later)
  • Buyer geolocation — kode pos pembeli (anonymized) untuk pemetaan demand regional
  • Live session logs — durasi streaming, jam mulai-selesai, host engagement

Output Fase 4: Raw data — events transaksi, live metadata, seller profiles, product catalogs (semua dengan PII anonymized).

Quality Checkpoint Fase 3-4
  • Anti-fraud detection — filter transaksi palsu, seller scam, fake reviews
  • Validasi API completeness (target > 98% events captured)
  • Privacy audit — verifikasi anonimisasi PII (UU 27/2022 PDP)
  • Retention policy: raw events 90 hari, agregat statistik 5+ tahun
  • Cross-check dengan Shopee dashboard seller (sample audit)

Fase 5-6 — Process & Analyse
GMV · AOV · QC vs BPS
Fase 5: Process (Olah Data)

Transformasi raw events menjadi data terstruktur siap analisis:

  • Data cleaning — filter fraud, return/refund, transaksi gagal, double counting
  • Validation — cross-check dengan Shopee seller dashboard & data BPS e-commerce
  • Geolocation mapping — tag seller Bandung (basis kode pos 40xxx) & buyer region
  • Agregasi — per jam, harian, mingguan, bulanan, per kategori produk, per kecamatan seller
  • Derivasi variabel: GMV = Σ nilai transaksi; AOV = GMV / jumlah order; conversion rate = buyers / viewers
  • Klasifikasi seller — UKM vs enterprise, kategori produk dominan, performa tier (platinum/gold/silver/bronze)

Output Fase 5: Clean structured data — siap analisis + input Metadata Variabel ke SIRUSA.

Fase 6: Analyse (Analisis Statistik)

Hitung statistik agregat & validasi kualitas:

  • Statistik GMV — harian/mingguan/bulanan Kota Bandung, per kategori, per kecamatan
  • Trending products — top 10 kategori & produk di Shopee Live Bandung
  • Bandung seller performance — ranking, growth rate, market share
  • Consumer behavior — peak hours live shopping, AOV per kategori, payment preference
  • MSME digitalization — tingkat adopsi Shopee Live oleh UMKM Bandung
  • Creative economy indicators — performa fashion & F&B Bandung (heritage city)
  • Cross-validation vs Statistik E-Commerce BPS & data Diskoperindag

Output Fase 6: Statistik siap publikasi + Quality Report + input Metadata Indikator ke SIRUSA.
